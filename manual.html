Timbre · Complete User Manual

From a blank project to a mastered, delivered piece.

This manual follows Timbre in the order the application is designed to be used. Every major screen is shown with focused crops of the exact interface, followed by the operating sequence, the purpose of each control group, and the points where a wrong setting propagates into later stages.

Before production

First run: get the engine into a usable state

Timbre separates the application from the speech runtime and model weights. A fresh installation therefore needs a runtime first, then at least one speech model. Once the engine is running, the status block remains visible at the lower-left of the application.

Open Engine.

Choose Engine from the left rail. Timbre inspects the machine and recommends the runtime build for the available GPU/backend.

Install the recommended runtime.

Use the recommended install button. During installation the row displays download/extraction progress. When complete, Timbre stores the runtime in its own application-data directory.

Open Models and install one speech model.

Choose a model that fits the available memory. The Studio/Voice controls only expose capabilities actually supported by the selected model.

Confirm the lower-left status reads Running.

If the engine is stopped, start it before generating narration. Stop Engine is useful when freeing GPU memory for another application.

macOS/Windows shortcut convention. Timbre treats Control and Command as the same modifier for the editor and stage navigation. This manual writes Cmd/Ctrl where either is accepted.

Library

Projects: create, import, resume and search

Create a new project.

Click + New Project. Set the project identity and format, then continue into Brief. The project receives its own folder and is autosaved with rolling snapshots.

Resume an existing project.

Click Continue on a card. Timbre restores the project and opens the production pipeline.

Bring in another Timbre project.

Use Import Project File…. This is for a project document/package, not ordinary video or audio media; media belongs in the Edit stage.

Filter a larger library.

Use Search projects… for the project name and All formats to narrow the library to the intended output type.

01 · Brief

Define the production constraints before writing

Choose Format and Duration first.

These two fields define the target canvas/runtime envelope. A one-minute YouTube video, for example, gives the Script stage a finite word budget rather than an open-ended page.

Write the Objective as an outcome.

State what the audience should understand, feel or do by the end. Avoid a topic label such as “AI”; write the intended result, such as “Understand why local inference changes privacy and cost.”

Define the Audience.

Record who the piece is for and what they already know. The Script stage uses this context when evaluating opening clarity, premise density and explanatory burden.

Set language and actual reading speed.

Reading speed is measured from generated/recorded takes when available. The script duration estimate uses this measured value rather than a fixed generic WPM.

Select every distribution platform that matters.

The platform choice affects delivery loudness, format and export expectations. Do this here rather than compensating manually at the end.

Select tone deliberately, then inspect “This brief sets”.

The summary panel is the sanity check. If canvas, pacing, shot cadence or loudness are wrong, correct the brief now before generating script, voice and edits.

Click Next: Script.

This advances to stage 02 while preserving every brief-derived constraint.

02 · Script

Build the narration as timed sections, not one text block

Choose or create the narrative structure.

Use Architect when you want a deliberate sequence of hook, setup, context, conflict, explanation, example, reveal, payoff and CTA rather than manually creating sections.

Write one idea per section.

Use the section title as a compact statement of intent. This keeps voice direction, visuals and later edits aligned to the same semantic unit.

Watch estimated duration while you write.

The large right-hand duration is calculated from words and measured reading speed. Treat an overrun as a structural problem: cut or combine ideas before generating narration.

Resolve highlighted checks.

Warnings can include overly long first sentences, weak opening patterns, unsupported factual claims, generic premises and complexity. They are review signals, not automatic rewrites.

Use Import only for source text you intend to structure.

An imported wall of prose still benefits from sectioning. Split it before voice generation so pauses, performance direction and shot planning can follow the narrative architecture.

Advance only when the runtime is plausible.

Click Next: Voice when section durations and the total estimate are within the intended brief.

03 · Voice

Choose an identity, then direct the performance

Select the voice identity scope.

This project only keeps the configuration local to the project. Use Save as Identity when you want the same model/reference/direction available later.

Select a Model.

Only installed speech models appear. The mode and generation controls change according to the model specification, so unsupported settings are not sent to the engine.

Choose Design, Clone or Preset.

Design builds a voice from a written description. Clone uses a saved reference voice. Preset selects voices bundled with models that provide them.

For cloning, use a clean 5–15 second reference.

Use one speaker, low background noise and an exact transcript. A mismatched transcript harms identity/prosody conditioning because the engine must align the reference content.

Direct the read with performance controls.

Energy, Authority, Intimacy, Tension and Warmth describe delivery rather than simple pitch shifts. Set pacing separately: Slow, Measured, Conversational, Brisk or Rapid.

Set deterministic details.

A pinned seed helps reproduce takes. Write numbers out before speaking converts forms such as “1,094” into spoken words. Gap between sections controls the real silence inserted between section takes.

Generate and audition before moving on.

Listen for pronunciation, breath placement, section joins and performance consistency. Fix the source text or pronunciation before compensating in the editor.

Voice cloning: use only recordings you have permission to use. The Voice Library retains descriptive/credit information so provenance can remain attached to the reference.

04 · Visuals

Turn narration timing into a shot plan

Select Density.

Sparse holds shots longer, Balanced increases coverage, and Dense creates faster visual turnover. The shot strip shows type and duration at a glance.

Review each proposal, not only the strip.

Each card shows the spoken line, shot type, treatment, description/title and the reasoning behind the recommendation.

Change the shot type when the idea needs another visual grammar.

Typical choices include Typography, Stock, Generated, Diagram and Hold. The purpose is semantic fit, not variety for its own sake.

Attach media.

Use Link from the bin… for media already imported into the project or Import… for new material.

Approve or Reject.

Approval indicates the shot is ready to be used. Rejected ideas can be hidden with Show rejected off while preserving the decision for later review.

Place on Timeline.

Once the plan is credible, use Place on Timeline to move the selected/approved decisions into Edit with narration timing as the reference.

05 · Edit

Assemble picture, narration, music and effects on the timeline

Import media.

Click Import or drag video, audio or stills into the application. Media appears in the bin and can be placed on the timeline.

Use the bin tabs by role.

Media holds imported assets, Narration exposes generated speech, and Sound is for generated/imported sound material.

Arrange clips directly.

Drag to move. Drag an edge to trim. Drag vertically to another compatible track. Snapping aligns clip edges and the playhead when Snap is enabled.

Use the correct edit tool.

Select, Razor, Slip, Slide, Roll and Volume automation are distinct operations. Tool hotkeys are listed in the reference section below.

Inspect the selected clip.

The Inspector controls fit/fill, crop, transform, opacity, colour parameters, fades, transitions, speed, reverse and clip gain. Make per-clip visual changes here rather than destructively modifying the source file.

Mix by track role.

The Mixer exposes polarity, high-pass, gate, EQ, compression, pan, fader, metering and master controls. Narration can side-chain/duck a music bed automatically.

Use range and edit-point navigation for precision.

Mark In/Out, shuttle with J/K/L, move between edits with Arrow Up/Down and use frame-step or nudge commands when mouse dragging is too coarse.

Preview, then proceed to Master.

What you hear in the editor is built from the same project signal-chain definitions used by offline rendering; use the Master stage for delivery-level measurement and final processing.

Track controls at a glance

M — MuteSilences the track without deleting clips.
S — SoloAuditions the track against muted peers.
VisibilityToggles video-track compositing visibility where applicable.

OverflowMove track in the stack, duplicate the strip to an empty track, or remove the track.

06 · Master

Measure against a delivery target, then finish the signal path

Select the mastering profile by programme type.

Documentary, Podcast, Advertisement, TikTok/Reels, Broadcast, Educational Lecture and Cinematic alter the intended programme behaviour. Delivery platform loudness remains a separate target established by the brief.

Click Measure Only when you want diagnosis first.

Timbre evaluates integrated loudness, true peak, loudness range and voice/bed relationship without asking you to commit the master operation.

Read the large LUFS number against the target rail.

The main display answers the basic delivery question directly: how far the measured mix is from the target. Do not judge only by peak level; integrated loudness and true peak solve different problems.

Inspect True Peak, Range and Voice/Bed.

True Peak protects encoding headroom, Range describes programme dynamics, and Voice/Bed checks whether narration remains sufficiently above the supporting bed.

Click Master when the profile is correct.

The application uses measured project data to propose/apply the required gain and track moves rather than relying on a fixed “make louder” preset.

Rack header and runtime

IN/OUT engages or bypasses the whole insert. Runtime state reads DSP READY, PREPARING or DSP OFFLINE. If not installed, Install engine prepares the local processing runtime.

Master Monitor

ARM prints a 12-second audition loop; after a result exists the same button becomes REFRESH. PLAY auditions it. Readouts include I, TP, LRA, S MAX and M MAX.

Auto Adapt

AUTO ADAPT analyzes programme metrics and applies a measured insert configuration. UNDO restores the previous chain after an adaptive pass.

Processors and plug-ins

Choose a built-in processor from the add selector or use VST3 / AU for an external processor. Each unit has bypass, live response display, live metrics, effect parameters, a MIX control, move-earlier/move-later buttons and Remove.

Signal-order rule: the rack is explicitly labelled “Pre-master insert · Timbre final loudness + limiter remain last.” Use insert processing for tone/dynamics; let the final master stage preserve the delivery target.

07 · Shorts

Find vertical clips from the finished long-form piece

Shorts works from word-timed source material. It can use the current project timeline or another source video, transcribe locally, rank candidate segments, reframe them to 9:16, and burn captions using the same final rendering path used for export.

Choose the long-form source.

Use Choose the video… for an external finished file or Use this project’s timeline to cut directly from the edit you have built in Timbre.

Create word timings.

Click Transcribe when a local transcription model is installed, or Import captions… if timings already exist. Word-accurate timing allows caption boundaries to follow speech rather than rough sentence blocks.

Set the search window.

Choose how many candidates to find, minimum duration, maximum duration and the target duration. These settings constrain the search without rewriting the source.

Click Find clips.

Candidates are scored using opening strength, ability to stand alone, story arc, ending, clean edges, pace, length and style fit.

Review each candidate.

Use Keep or Reject. The card shows why the clip was selected, its opening and closing lines, and a 9:16 crop preview when source video is available.

Correct trim and caption timing where required.

Trim… changes in/out points. Text timing… exposes global offset, timing stretch, individual title-frame In/Out controls, ±0.10 second nudges, playhead assignment and an exact rendered caption preview.

Render one or render the kept set.

Render this one is useful for a test. Render N vertical renders all kept candidates. Final shorts are 1080×1920 at 30 fps in the current caption-render path.

Click Next: deliver.

Move to the packaging/export stage only after the short list and caption timing are accepted.

08 · Deliver

Export the video and the project package

Deliver is the final quality gate. It compares the finished project against the brief, lets you fix a failed check by jumping back to the relevant stage, then writes the requested outputs locally.

Read “Against the brief”.

The checklist reports how many delivery conditions are clear. Where a failed/close check maps to an earlier stage, use Fix to jump directly to the relevant production page.

Choose Video preset and Encoder.

The video preset controls the output target; encoder selection chooses the available render backend. The mix is measured before encoding, so one exact gain can be applied to the master target rather than a moving estimate.

Click Export video.

This renders the finished timeline with its picture edits, audio mix and delivery loudness. Use Stop if you need to cancel an active job.

Select package contents.

The Package panel lets you choose additional deliverables/interchange items. Group-level All/None controls speed up selection.

Click Export package.

Selected items are written to one folder adjacent to the project name. The interface also explains what a chosen interchange format cannot carry so you do not assume an external editor will reproduce unsupported state.

Use Reveal after export.

Reveal opens the file/folder location in the operating system. Timbre does not upload delivery files automatically.

Library · Models

Install models that match the job and the machine

Read the tier and size before installing.

Flagship models maximize quality but demand more GPU memory. Balanced and lighter models trade model size for faster/lower-memory operation.

Match capability to the workflow.

Not every model supports Design, Clone and Preset. Multilingual, Indian-language, streaming, sound/music and transcription models serve different tasks.

Install only what is needed.

Model packages can range from hundreds of megabytes to several gigabytes. Timbre keeps one speech model resident at a time to avoid stacking weights in VRAM.

Check licensing for production use.

Model code and model weights can carry different licences. The catalogue surfaces model licensing information before download; commercial projects should use weights whose licence permits the intended use.

Library · Voices

Build a reusable reference-voice library

Click Add a Voice.

Select the clean reference recording, then enter the exact transcript of what is spoken. Keep one speaker in the file.

Record identity/provenance information.

Use a descriptive name and retain credit/permission context. A voice should remain identifiable after months of project work.

Use the saved voice from stage 03.

In Voice, choose Clone and select the reference from the Reference voice menu. Clone-only models rely on this library instead of a Design prompt.

Edit or delete deliberately.

Changing a reference can change future renders. Existing project media remains rendered audio, but regeneration may sound different after a reference is replaced.

End-to-end operating sequence

A repeatable production checklist

01Brief
02Script
03Voice
04Visuals
05Edit
06Master
07Shorts
08Deliver
Brief locks the constraints.

Runtime, audience, platform, pacing and delivery targets should be credible before any expensive generation work.

Script locks the semantic structure.

Get the opening, argument and word count right before creating performance takes.

Voice locks timing and performance.

Regenerate mispronunciations or poorly directed lines here rather than attempting to repair them with timeline effects.

Visuals turns timing into coverage.

Approve the visual logic and attach available media before bulk-placement on the timeline.

Edit locks the programme.

Picture, narration, bed, SFX, fades, transitions and mix automation should be settled before mastering.

Master verifies delivery, not taste alone.

Use LUFS, true peak, dynamic range and voice/bed measurements; use the insert rack for controlled tone/dynamics, keeping final loudness downstream.

Shorts is derivative work.

Cut from the finished long piece so captions, crop decisions and clip scoring reference the final narrative.

Deliver is the last gate.

Resolve failed checks, export video, export the package, and reveal the resulting local files.

When something sounds wrong

Fix the earliest stage that caused it. Wrong wording → Script. Wrong delivery → Voice. Wrong level balance → Edit/Mixer. Wrong delivery loudness → Master. Do not solve an upstream problem by stacking downstream processing.

When something looks wrong

Shot concept → Visuals. Timing/composition/crop → Edit Inspector and timeline. Platform framing/output size → Brief/Deliver preset. Keep conceptual, editorial and delivery decisions in their own stages.

About Timbre

Timbre was created at Axiomatic Research Lab by Godson Johnson.

Timbre is an integrated creative-production environment designed to bring narrative development, voice generation, visual planning, editing, mixing, mastering, short-form adaptation, and final delivery into a single coherent workflow.

The project reflects Axiomatic Research Lab’s broader work in human–AI creative systems: tools in which artificial intelligence supports the creator’s judgement rather than replacing it. Timbre is therefore designed around direct control, measurable feedback, editable intermediate stages, and a production workflow that keeps the user responsible for the final creative and technical decisions.

This manual documents the interface and operating model of the supplied Timbre build, including its current project workflow, editor, mixer, mastering environment, processor rack, voice tools, visual planning system, Shorts workflow, and delivery controls.
